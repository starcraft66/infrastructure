= OpenBao agent AppRole provisioning

The NixOS `vault-agent-*` units run the OpenBao binary in agent mode. The unit
names retain the NixOS module's Vault-compatible naming, but no HashiCorp Vault
binary is used.

Apply the OpenTofu configuration before provisioning credentials. It creates
separate AppRoles for the control plane, workers, CoreDNS, etcd, and Patroni.

Generate a distinct SecretID for every AppRole on every node. Role IDs may be
shared between nodes assigned the same AppRole. Do not store RoleIDs, SecretIDs,
or tokens in this repository or pass SecretIDs as command-line arguments.

The expected credential files are:

[cols="2,2,2"]
|===
|Agent |AppRole suffix |Credential prefix

|Kubernetes control plane
|`node-kubernetes-control-plane`
|`/var/lib/secrets/kubernetes/vault_agent_control-plane`

|Kubernetes worker
|`node-kubernetes-worker`
|`/var/lib/secrets/kubernetes/vault_agent_worker`

|CoreDNS
|`node-coredns`
|`/var/lib/secrets/coredns/vault_agent`

|etcd
|`node-etcd`
|`/var/lib/secrets/etcd/vault_agent`

|Patroni
|`node-patroni`
|`/var/lib/secrets/patroni/vault_agent`
|===

For each target host, transfer the RoleID and a freshly generated SecretID over
standard input and install them with mode `0400` and the service's user/group.
For example, while authenticated to the current Vault or OpenBao leader:

[source,bash]
----
cluster_name="k8s-235-1"
target="stormfeather.235.tdude.co"

install_credential() {
  role="$1"
  owner="$2"
  prefix="$3"

  bao read -field=role_id "auth/approle/role/${cluster_name}-${role}/role-id" |
    ssh "root@${target}" "install -D -m 0400 -o ${owner} -g ${owner} /dev/stdin ${prefix}_role_id"
  bao write -field=secret_id -f "auth/approle/role/${cluster_name}-${role}/secret-id" |
    ssh "root@${target}" "install -D -m 0400 -o ${owner} -g ${owner} /dev/stdin ${prefix}_secret_id"
}

install_credential node-kubernetes-control-plane kubernetes \
  /var/lib/secrets/kubernetes/vault_agent_control-plane
install_credential node-kubernetes-worker kubernetes \
  /var/lib/secrets/kubernetes/vault_agent_worker
install_credential node-coredns coredns \
  /var/lib/secrets/coredns/vault_agent
install_credential node-etcd etcd \
  /var/lib/secrets/etcd/vault_agent
install_credential node-patroni patroni \
  /var/lib/secrets/patroni/vault_agent
----

Omit Patroni on clusters or nodes where it is not enabled. Provision all files
before deploying the NixOS configuration: the deployment switches agents to
the new paths atomically.

After deployment, confirm every unit can authenticate and render a certificate:

[source,console]
----
systemctl --failed
systemctl status vault-agent-{kubernetes-control-plane,kubernetes-worker,coredns,etcd,patroni}
journalctl -u 'vault-agent-*' --since=-10m
----

The legacy `${CLUSTER_NAME}-node-kubernetes` AppRole and broad
`kubernetes-issue` policy were removed after every node was verified on the
scoped credentials.

== Build the admin kubeconfig

Pocket ID is the Kubernetes OIDC provider. The Vault identity OIDC provider is
not required. To bootstrap authorization, use the PKI-issued administrator
certificate already rendered on a control-plane node:

[source,bash]
----
cluster_name="k8s-305-1700-1"
admin_user="admin"
context_name="admin@${cluster_name}"
server="https://k8s.305-1700.tdude.co"
cert_dir="/var/lib/secrets/kubernetes"

kubectl config set-cluster "$cluster_name" \
  --certificate-authority="${cert_dir}/kubernetes-ca.pem" \
  --embed-certs=true \
  --server="$server" \
  --kubeconfig=admin.kubeconfig

kubectl config set-credentials "$admin_user" \
  --client-certificate="${cert_dir}/admin.pem" \
  --client-key="${cert_dir}/admin-key.pem" \
  --embed-certs=true \
  --kubeconfig=admin.kubeconfig

kubectl config set-context "$context_name" \
  --cluster="$cluster_name" \
  --user="$admin_user" \
  --kubeconfig=admin.kubeconfig

kubectl config use-context "$context_name" --kubeconfig=admin.kubeconfig
----
